# Project context

> Read this before any project work. Everything stack-specific lives here so the
> portable kit stays generic.

## Stack — framework & runtime

- **Backend:** Python 3.11+, FastAPI, Uvicorn, SQLAlchemy, SQLite (v1), Pydantic v2 / pydantic-settings, pandas.
- **Frontend:** React 19, Vite, TypeScript (strict), Tailwind CSS v4 (via `@tailwindcss/vite`, no separate config file needed).
- **Monorepo:** `backend/` and `frontend/` are independent projects in the same repo — no shared package manager or build step between them.

## Solution & folder layout

- `backend/app/core/` — `Settings` (env-driven config), enums (`Symbol`, `Timeframe`, `Direction`, `FeedStatus`, `FeedProvider`), logging, exceptions.
- `backend/app/feeds/` — `MarketDataProvider` adapter interface (`connect`/`disconnect`/`stream_ticks`/`fetch_history`/`nominal_status` — every provider implements all five) + implementations: `MockMarketDataProvider` (synthetic; ticks on a virtual clock, not wall-clock time — `time_acceleration`, via `Settings.mock_time_acceleration`, default 60x, compresses a 4H candle into ~4 real minutes; `fetch_history` returns `[]`, a deliberate no-op, since a synthetic feed has no history to backfill), `TwelveDataProvider` (real feed — see below), `FallbackMarketDataProvider` (composite — see below). `factory.py` (`create_provider(settings)`) is the one place that branches on `Settings.feed_provider`; nothing else should. Nothing outside `app/feeds/` should depend on a concrete provider class.
- `backend/app/feeds/fallback_provider.py` — `FallbackMarketDataProvider` wraps a priority-ordered list of providers (`create_provider` uses `[TwelveDataProvider, MockMarketDataProvider]` whenever a real feed is selected — PROJECT.md requires a "safe fallback if live feed is unavailable," and the mock feed always works since it has no external dependency). Falls back to the next provider **immediately** inside a single `stream_ticks()` call the moment the current one fails — it doesn't wait out `FeedService`'s own reconnect backoff, the two mechanisms compose rather than duplicate each other. While parked on a fallback, it deliberately ends the stream after `fallback_max_duration_seconds` (default 300s) even though nothing failed, so `FeedService`'s existing "stream ended → reconnect → retry" handling gives the primary another chance periodically instead of staying on the fallback forever after one blip. `nominal_status` reflects whichever sub-provider is currently active — this is why `FeedService` reads `provider.nominal_status` live rather than caching it once. Verified live: booting with `FEED_PROVIDER=twelve_data` reports `FeedStatus.LIVE` (the primary), not `MOCK`, confirming the wrapper correctly delegates when the primary is healthy.
- `backend/app/feeds/twelve_data_provider.py` — real market data via [Twelve Data](https://twelvedata.com)'s REST + WebSocket API (`fetch_history` → `GET /time_series`, `stream_ticks` → `wss://ws.twelvedata.com/v1/quotes/price`), selected via `FEED_PROVIDER=twelve_data` + `TWELVE_DATA_API_KEY`. Verified live against a free "Basic" plan account: historical candles and live WebSocket pushes both work for XAU/USD, EUR/USD, and AUD/USD. Two things that aren't obvious from the API and must not regress: (1) `time_series`'s `datetime` field is **not UTC by default** (confirmed empirically — the same candle came back ~10 hours apart depending on the `timezone` param), so every request explicitly passes `timezone=UTC`; (2) forex/commodities are OTC — there is no real trade volume, so every `Tick`/`Candle` this provider produces carries `volume=0.0` (see [[twelve-data-provider]] in decisions.md). `fetch_history` throttles itself to stay under the free tier's 8-requests/minute cap (`_MIN_REQUEST_INTERVAL_SECONDS`); `http_client`/`ws_connect` are constructor-injectable so tests never hit the real network (`httpx.MockTransport` + a hand-rolled fake WS connection, matching this codebase's existing fake-over-mocking-library convention).
- `backend/app/storage/` — `database.py` (lazy async engine/session factory via `get_engine()`/`get_session_factory()`, both `lru_cache`d — never construct the engine at import time), `types.py` (`UTCDateTime` — every datetime column must use this, not `DateTime(timezone=True)` directly; see [[utc-datetime-decision]] in decisions.md), `models.py` (`CandleORM`, `PredictionORM` — both append-only, rows never updated; `SignalORM` — the one table this codebase mutates after insert, since a signal has a real lifecycle open→win/loss/expired). `repositories/candle_repository.py` translates both ways — reads (`get_recent`/`get_latest`) return domain `Candle` objects, never `CandleORM`; `save_many_if_missing` bulk-inserts via `ON CONFLICT DO NOTHING` on the `(symbol, timeframe, open_time)` unique index, for idempotent historical backfill that may overlap with already-stored rows — `save()` (single-candle, live ingestion path) is unchanged and still raises on a duplicate, which is correct there (a live duplicate would be a real bug, not an expected overlap). `repositories/prediction_repository.py` only has one caller (the predictions router) so far, so its reads still return `PredictionORM` rows — apply the same domain-return refactor there if/when a second caller needs it (YAGNI: don't do it speculatively). `repositories/signal_repository.py` translates `SignalORM` ↔ the domain `Signal` dataclass both ways, plus `update_outcome()` for resolving a signal.
- `backend/app/features/` — `indicators.py` (SMA fast/slow, RSI, ATR, momentum, volatility — vectorized pandas functions, periods are named constants), `structure.py` (`SwingPoint`/`detect_swing_points`/`detect_break_of_structure` from Phase 2, plus `detect_sweeps`/`detect_structure_breaks` (CHoCH vs. BOS)/`weak_points` for the ICT pipeline — see [docs/signal-method.md](../../docs/signal-method.md)), `feature_builder.py` (`build_feature_set` — the only entry point the Phase 3 `rule_based.py` strategy should import from this package), `poi.py` (`detect_order_blocks`, `detect_fair_value_gaps` — Point of Interest detection), `fibonacci.py` (`compute_ote_zone` — the 70.5%-79% Optimal Trade Entry zone), `volume_profile.py` (`compute_volume_profile` — Fixed Range Volume Profile, POC/Value Area, used as a POI confluence tiebreaker; returns `None` if every candle in the range has zero volume, not a meaningless "POC" from an all-zero distribution — real forex/commodity feeds report no volume at all, unlike the mock feed's synthetic one).
- `backend/app/prediction/` — `base.py` (`Prediction`/`PredictionSignal` dataclasses + the `PredictionStrategy` ABC — the Phase 3 rule-based path), `rule_based.py` (`RuleBasedStrategy` — v1 weighted-vote heuristic; `RSI_BULLISH_THRESHOLD`/`RSI_BEARISH_THRESHOLD` are public module constants, not underscore-prefixed, specifically because `api/routers/config.py` is a second real reader of them — see [docs/prediction-method.md](../../docs/prediction-method.md)), `engine.py` (`PredictionEngine` + shared `CANDLE_WINDOW` constant), `signal.py` (`Signal`/`SignalStatus` — the ICT pipeline's domain type; unlike `Prediction`, a `Signal` carries an `id` once persisted because it has a real lifecycle to track), `signal_builder.py` (`build_signal` — the 4H bias → 1H setup → 15m entry pipeline; returns `None` unless every stage confirms and R:R ≥ 1.8; see [docs/signal-method.md](../../docs/signal-method.md) for the full writeup). Two independent prediction paths coexist deliberately: `rule_based.py` scores every candle close, `signal_builder.py` only ever produces winning-caliber, fully-specified setups.
- `backend/app/services/` — `candle_aggregator.py` (pure, no I/O — rolls ticks into per-timeframe OHLC `Candle`s), `candle_close_handler.py` (`CandleCloseHandler` — a `Protocol` for anything reacting to a closed candle; `FeedService` holds a `list[CandleCloseHandler]` rather than a named constructor param per reaction, since three now exist), `feed_service.py` (owns the provider lifecycle; per tick: caches latest price + broadcasts a price message; per closed candle: persists it, then runs every registered handler; if the provider's tick stream raises or ends, `_run` reconnects with capped exponential backoff — `_INITIAL_RECONNECT_DELAY_SECONDS`/`_MAX_RECONNECT_DELAY_SECONDS`/`_RECONNECT_BACKOFF_MULTIPLIER` — broadcasting `FeedStatus.DISCONNECTED` for the duration and back to the provider's own `nominal_status` (read live from `provider.nominal_status` each time, never cached — see [[fallback-provider-chain]] in decisions.md for why) once ticks resume; see [[feed-reconnect-backoff]] in decisions.md; `backfill()` fetches+persists missing historical candles per configured symbol/timeframe via `provider.fetch_history()` before `start()` begins live streaming — called explicitly from `main.py`'s `_lifespan`, not automatically inside `start()` — one symbol/timeframe failing doesn't abort the rest; see [[historical-backfill]] in decisions.md), `connection_manager.py` (registry of live WebSocket clients; best-effort broadcast), `broadcast_service.py` (translates domain `Tick`/`Prediction`/`FeedStatus`/`Signal` into `app/schemas/websocket_messages.py` wire types; the only thing that imports `ConnectionManager`), `prediction_service.py` (`CandleCloseHandler` — event-driven Phase 3 prediction scheduling; see [[event-driven-prediction-scheduling]] in decisions.md), `signal_tracker.py` (`CandleCloseHandler` — resolves OPEN signals to WIN/LOSS/EXPIRED against each new candle of the signal's own `entry_timeframe`; a candle hitting both stop and target is conservatively scored a LOSS), `signal_service.py` (`CandleCloseHandler` — only acts on 15m candle closes; fetches the 4H/1H/15m windows and runs `build_signal()`, persisting+broadcasting anything produced).
- `backend/app/api/routers/` — REST endpoints, one router per resource: `health.py`, `config.py` (`GET /config` — curated, **read-only** view of effective `Settings` + the ICT/prediction module constants; no PUT/PATCH, since `Settings` is `lru_cache`d at startup and the strategy constants aren't persisted config yet — see `docs/architecture.md`'s Phase 7 note), `symbols.py`, `prices.py` (latest tick per symbol, from `FeedService`'s in-memory cache), `candles.py` (recent closed candles from SQLite), `predictions.py` (Phase 3 rule-based: `GET .../latest` computes on demand and logs; `GET .../history` reads back), `signals.py` (ICT pipeline, read-only — no POST; `GET /signals/open` optionally filtered by symbol, `GET /signals/{symbol}/history` including resolved outcomes), `websocket.py` (`/ws` — broadcast-only; sends the connecting client `FeedService.status` immediately on connect, then just drains incoming messages to keep the socket alive). Symbol/timeframe are typed enum path params everywhere, not free text.
- `backend/app/api/dependencies.py` — shared FastAPI dependency accessors: `get_feed_service` (reads `request.app.state.feed_service`), `get_prediction_engine` (`lru_cache`d — same lazy-construction pattern as `storage/database.py`, so it stays import-side-effect-free and overridable in tests; safe only because `RuleBasedStrategy`/`PredictionEngine` are stateless — move to `app.state` if a future strategy carries state).
- `backend/app/main.py` — `create_app()` factory; the mock feed is started/stopped via a FastAPI `lifespan` context manager, not `on_event` (deprecated). No module-level side effects beyond the final `app = create_app()`, so tests can build isolated instances. `app.middleware("http")(add_security_headers)` is registered before the CORS middleware.
- `backend/app/core/security_headers.py` — `add_security_headers` (a plain `@app.middleware("http")`-style function, not a class) sets CSP/`X-Content-Type-Options`/`X-Frame-Options`/`Referrer-Policy`/HSTS on every HTTP response; doesn't touch the `/ws` handshake. The CSP allow-lists `cdn.jsdelivr.net` specifically so FastAPI's built-in `/docs` (Swagger UI) keeps working under a `default-src 'self'` policy.
- `backend/pytest.ini` — sets `pythonpath = .` (so `app.*` imports resolve regardless of invocation cwd), `asyncio_mode = auto` (async `def test_...` functions run without a `@pytest.mark.asyncio` decorator on every one), and `addopts = --cov=app --cov-report=term-missing --cov-fail-under=80` (Phase 8) — a bare `pytest` run always enforces the 80% coverage gate from [.claude/rules/code-review.md](../rules/code-review.md); no separate `.coveragerc`, since the repo-wide total (89% as of Phase 8) already clears the threshold without needing per-file `omit` tuning.
- `frontend/src/types/` — `market.ts` (`MarketSymbol`/`Timeframe`/`Direction`/`FeedStatus`/`Candle`/`Price`), `prediction.ts`, `signal.ts`, `websocket.ts` (`WebSocketMessage` discriminated union). Field names deliberately match the backend's wire format (snake_case) exactly — no camelCase transform layer, to avoid a hand-maintained mapping that could drift from the API.
- `frontend/src/services/` — `apiClient.ts` (`apiGet<T>`, `ApiError`), `api.ts` (one function per REST endpoint: `getSymbols`, `getCandles`, `getOpenSignals`, `getSignalHistory`, `getPredictionHistory`).
- `frontend/src/store/marketStore.ts` — a Zustand store fed by the WebSocket (`useMarketSocket`): `feedStatus`, `prices` (by symbol), `predictions` (by `symbol:timeframe`), `signals` (by id — both new-open and later resolution updates land in the same slot). `selectOpenSignals` derives a filtered+sorted list; **any selector like it that returns a new array/object per call must be wrapped in `useShallow` from `zustand/react/shallow`** at the call site, or React's `useSyncExternalStore` treats every render as a new snapshot and infinite-loops (`"The result of getSnapshot should be cached"` — hit and fixed in `SignalFeed.tsx`).
- `frontend/src/hooks/` — `useMarketSocket.ts` (owns the WebSocket connection + reconnect with capped exponential backoff, reset to the initial delay on a successful `onopen`; dispatches every message into the store; `onerror` surfaces a `disconnected` feed status instead of only logging), `useSymbols.ts`, `useOpenSignalsBootstrap.ts` (React Query fetch-once-on-mount to seed `signals`, which the WebSocket then keeps live), `useCandles.ts`, `useSignalHistory.ts`, `usePredictionHistory.ts` (React Query wrappers for the Symbol Detail view — refetch automatically when the selected symbol/timeframe changes, since they're in the query key).
- `frontend/src/components/dashboard/` — `DisclaimerBanner.tsx` (Phase 0), `FeedStatusIndicator.tsx`, `SymbolCard.tsx`, `DirectionBadge.tsx`, `SignalStatusBadge.tsx`, `SignalCard.tsx`, `SignalFeed.tsx` (the dashboard's centerpiece), `PredictionPanel.tsx` (secondary, live Phase 3 predictions), `SymbolTimeframeSelector.tsx`, `PriceChart.tsx` (`lightweight-charts` candlestick series; entry/stop/target drawn as price lines for the open signal on that symbol, if any), `SignalHistoryTable.tsx`, `PredictionHistoryTable.tsx`, `PerformanceStats.tsx` (win rate / avg realized R:R / totals, computed client-side from fetched signal history — no backend aggregation endpoint, YAGNI until a second consumer needs one), `SymbolDetail.tsx` (assembles the selector + chart + stats + both history tables; owns the local `symbol`/`timeframe` selection state).
- `frontend/src/utils/performanceStats.ts` — `computePerformanceStats` (pure; win rate excludes `expired`/`open` from the denominator, average realized R:R is over WIN/LOSS only). First piece of frontend business logic worth a unit test — see `performanceStats.test.ts` and the Vitest setup below.
- `frontend/src/components/layout/AppShell.tsx` — shared header (title + nav links via `react-router-dom`'s `NavLink`) + `DisclaimerBanner` + `FeedStatusIndicator`, wrapping `children` in a `<main>`. Both `DashboardPage` and `SettingsPage` render through it so the chrome (nav, disclaimer, feed status) can't drift between pages.
- `frontend/src/hooks/useConfig.ts` — React Query wrapper around `getConfig()` (`GET /config`); read-only, no mutation hook, matching the backend's read-only `/config` endpoint.
- `frontend/src/pages/DashboardPage.tsx` — assembles the dashboard sections inside `AppShell`; does **not** call `useMarketSocket()` itself.
- `frontend/src/pages/SettingsPage.tsx` — read-only grouped display of `useConfig()`'s data (Feed / ICT Signal Pipeline / Rule-Based Prediction sections), inside `AppShell`.
- `frontend/src/App.tsx` — calls `useMarketSocket()` exactly once, above `<Routes>` (`/` → `DashboardPage`, `/settings` → `SettingsPage`), so the WebSocket connection survives route navigation instead of reconnecting per page — see [[websocket-hook-at-app-level]] in decisions.md. `main.tsx` wraps the tree in `BrowserRouter` + `QueryClientProvider`.
- `backend/app/backtesting/` — walk-forward backtesting over real historical data, avoiding lookahead bias (a simulated "as of" point may only see candles that would genuinely have closed by then). `signal_resolution.py` (in `app/prediction/`, not this package) holds `resolve_signal()`, extracted from `SignalTracker` so live and backtested outcomes are graded by the identical rule. `signal_backtest.py` (`run_signal_backtest`) replays `build_signal()` at every 15m close using a two-pointer walk (O(n), not re-filtering the whole history per step) to window 4H/1H/15m candles as-of each point; `prediction_backtest.py` (`run_prediction_backtest`) replays the rule-based `PredictionEngine`/`RuleBasedStrategy` per timeframe, scoring each non-neutral call against whether the very next candle's close moved the predicted direction (this is what finally gives [TD-2](tech-debt.md) real evidence instead of a guess). Both engines' window sizes are constructor-overridable (defaulting to the real live constants from `signal_service.py`/`engine.py`) specifically so tests don't need 60+/100+/20+ real candles to exercise the walk-forward/warmup logic. `models.py` (`BacktestRun`/`BacktestKind`) is the persisted-run domain type. `cli.py` (`python -m app.backtesting.cli`) is the only way to actually run a backtest — it fetches history directly via a bare `TwelveDataProvider` (deliberately bypassing `factory.py`'s fallback wrapping, since a backtest must fail loudly on a real fetch problem, not silently substitute the mock feed's much shorter synthetic history), prints a summary, and persists it. See [[backtesting-engine]] in decisions.md.
- `backend/app/storage/models.py` — `BacktestRunORM` (append-only, like `CandleORM`/`PredictionORM` — a backtest run is a point-in-time fact, never mutated after saving); `repositories/backtest_run_repository.py` translates it to/from the domain `BacktestRun`. `summary` is JSON-encoded (matching `SignalORM.details`'s convention) since its shape differs by `kind` (signal vs. prediction backtests report different stats).
- `backend/app/api/routers/backtests.py` — `GET /backtests` (optionally filtered by `symbol`/`kind`), read-only — no POST; a run is only ever produced by the CLI, which needs unthrottled, potentially minutes-long access to a real feed provider that a request/response cycle isn't suited for (YAGNI on background-job infrastructure until there's real demand for on-demand backtests from the UI).
- `docs/architecture.md` — full architecture + phase plan; keep in sync when the design changes.

## Key libraries

- **Backend config:** `pydantic-settings` — single `Settings` class in `app/core/config.py`, cached via `get_settings()`. Env vars map case-insensitively to field names (no prefix); list fields (`cors_origins`, `symbols`, `timeframes`) accept comma-separated strings via a `field_validator`.
- **Backend numerics:** `pandas`/`numpy` for indicator math (`app/features/indicators.py`) — vectorized over Series, not manual loops. Indicator periods (RSI/ATR 14, SMA 10/30, momentum 10, volatility 20) are named module constants, not tuned yet; revisit once backtesting (Phase 9) can score them.
- **Backend data access:** SQLAlchemy 2.0 async engine + `aiosqlite` driver (`sqlite+aiosqlite:///...`) — kept async to match the rest of the backend's async-throughout convention; see [[async-sqlalchemy-decision]] in decisions.md. Repositories own sessions; no ORM models leak past the repository layer — routers/services only ever see the domain `Candle`/`Tick` dataclasses from `app.feeds.base`.
- **Backend HTTP client:** `httpx.AsyncClient` — used both for the FastAPI test client and as `TwelveDataProvider`'s REST client (constructor-injectable so tests substitute `httpx.MockTransport` instead of hitting the real API; no `respx` or other mocking library added, per this codebase's hand-rolled-fake convention).
- **Backend WebSocket client:** `websockets` (already a dependency for the server side of `/ws`) doubles as `TwelveDataProvider`'s client for Twelve Data's real-time price stream; `ws_connect` is constructor-injectable for the same testability reason.
- **Backend testing:** pytest + pytest-asyncio + FastAPI `TestClient`/httpx, plus `pytest-cov` (Phase 8) for the coverage gate — see `pytest.ini` above. Test files must have a unique basename across `tests/unit/` and `tests/integration/` — neither directory has `__init__.py`, so two files sharing a name (e.g. `test_signal_tracker.py` in both) causes a pytest "import file mismatch" collection error. Suffix one (e.g. `_persistence`) if a name collision comes up.
- **Frontend styling:** Tailwind v4 utility classes directly in JSX; no CSS Modules/styled-components.
- **Frontend data fetching:** `@tanstack/react-query` for REST (one-shot fetch-and-cache, e.g. `useSymbols`, `useOpenSignalsBootstrap`) — not a hand-rolled `useEffect` fetch per component. `QueryClientProvider` wraps the tree in `main.tsx`.
- **Frontend live state:** `zustand` (`store/marketStore.ts`) for WebSocket-pushed state — push-driven data doesn't fit react-query's pull/cache model, so REST bootstraps initial state and the store takes over from there via `useMarketSocket`.
- **Frontend charting:** `lightweight-charts` v5 (free/Apache-2.0 tier) — series are created via `chart.addSeries(CandlestickSeries, options)` (the v5 tree-shakeable pattern; `CandlestickSeries` is a value import from the package, not a string). Price lines (`series.createPriceLine`) draw entry/stop/target; there's no "clear all price lines" API, so callers must track and `removePriceLine` the ones they created (see `PriceChart.tsx`'s cleanup effect). **The "TradingView" attribution logo on the chart must not be hidden or removed** — it's a license condition of the free tier, not a stray artifact; only TradingView's paid Advanced Charts library allows removing it.
- **Frontend testing:** Vitest (`npm test`) — added in Phase 6 for the first genuinely testable piece of business logic (`utils/performanceStats.ts`). No React Testing Library yet; add it when a component's behavior (not just a pure function) needs testing.
- **Frontend routing:** `react-router-dom` v7 — added in Phase 7 for the `/` (dashboard) and `/settings` routes. `BrowserRouter` wraps the tree in `main.tsx`; `App.tsx` only holds `<Routes>` plus the single `useMarketSocket()` call (see [[websocket-hook-at-app-level]] in decisions.md).

## Conventions & namespaces

- **Backend:** modules import as `app.<package>.<module>`; async I/O throughout (no sync-over-async); enums (`Symbol`, `Timeframe`, `Direction`, `FeedStatus`) instead of magic strings anywhere a value is one of a fixed set.
- **Frontend:** camelCase functions/variables, PascalCase components/types, kebab-case CSS classes/ids; TypeScript `strict: true` is enabled in `tsconfig.app.json`.
- **Feed provider swap:** adding a new market data source means a new class implementing `MarketDataProvider` in `app/feeds/` plus one branch in `app/feeds/factory.py`'s `create_provider` — never a second branch ladder scattered across calling code (`main.py` only ever calls `create_provider(settings)`).
- **No auto-trading:** there is no execution/order-placement module in this codebase by design, not as a disabled feature. Do not add one without an explicit, separate decision from the project owner.

## Build & run

- **Backend install:** `cd backend && py -m venv .venv && ./.venv/Scripts/pip install -r requirements.txt`
- **Backend run:** `./.venv/Scripts/uvicorn app.main:app --reload` (serves `http://localhost:8000`, health check at `/health`)
- **Backend test:** `./.venv/Scripts/pytest` (test suite added starting Phase 1)
- **Frontend install:** `cd frontend && npm install`
- **Frontend run:** `npm run dev` (serves `http://localhost:5173`)
- **Frontend build:** `npm run build` (runs `tsc -b` then `vite build`)
- **Frontend test:** `npm test` (`vitest run`)
- **Frontend lint:** `npm run lint` (oxlint)
